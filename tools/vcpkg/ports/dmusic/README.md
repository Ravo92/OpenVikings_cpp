# Native music package

This x64-only overlay pins [GothicKit/dmusic](https://github.com/GothicKit/dmusic) at commit `b73b270b94714b8ec8d9d0b2a9f3a5c445da52d1`. It builds `dmusic` and its bundled TinySoundFont implementation as static libraries with the dynamic MSVC runtime. The Win32 game continues to use the reconstructed COM driver. No game data, Windows sound collection or additional music DLL is distributed.

`cultures-pattern-tracks.patch` adds:

- Embedded RIFF `DMPT` pattern tracks, with independently scheduled parts, retained backing storage, instrument download and loop-start seeking.
- SDK `seqt` note/controller/curve records and `TIMS` time-signature tracks.
- Repeat control, current-playback queries, separate pending primary changes, loop durations that exclude the intro and finite completion.
- Global-style conductor commands only for actual external style tracks, with fully initialized fallback commands. Embedded patterns and sequence tracks retain independent scheduling; absent or empty styles do not enter random pattern selection.
- Queue/segment/style/DLS ownership corrections, safe native font-cache rebasing, DLS fine tuning and parser/init failure propagation.
- Explicit initialization of temporary message queues, checked capacity growth and complete cleanup/reset after queue allocation failures and release.
- Optional DLS sample/instrument names copied as bounded, terminated display metadata; absent `INFO/INAM` names are represented by empty strings.
- SDK octave transposition and fixed-to-key/chord note modes, explicit global-key propagation and a C-major-seven/major-scale fallback taken from the shipped chord data.
- A fractional musical clock advanced by rendered frames, with event dispatch on complete PCM frames and the render lock held through the entire output block.
- Installation of both required static libraries and the public header directly at `include/dmusic.h`. Debug uses `dmusicd.lib` plus `dmusic-tsf.lib`; Release uses `dmusic.lib` plus `dmusic-tsf.lib`. Port revision 2 fixes upstream's nested `include/include` installation and invalidates the preceding package cache.

The game adapter in `src/NativeMusicDriver.cpp` supplies a UTF-8/wide-file resolver and event-driven stereo PCM output through `waveOut`. Synthesis runs on its own thread, separately from the existing music command/file-loading worker. It joins before freeing buffers and music resources. The existing game manager selects events, controls volume and ducks music during speech. Musical randomness uses an isolated generator and never consumes the simulation RNG. Runtime state is not serialized.

The resolver searches the game's configured music directory, then the referenced basename for obsolete Producer paths. `gm.dls` additionally resolves from the Windows system `drivers` directory. Missing resources and synthesis/output failures are recorded with the existing `-log:renderer` option in `logs/renderer.log`. Useful events include `music_ready`, `music_segment_loaded`, `music_segment_started` and `music_*_failed`.

## Evidence and limits

A read-only inventory of the installed Eight Wonders music found 64 SGT scores: 60 use 605 embedded pattern tracks; four use 15 sequence tracks containing 5,517 note records. There are 49 game DLS files, whose waves are PCM. Some instruments additionally request the Windows General MIDI collection. All inspected scores have a nonzero loop start; their loop end equals their segment length. Three scores use 3/4 and the others 4/4. File structures follow the [DirectMusic SDK pattern form](https://documentation.help/DirectMusic/patterntrackform.htm), [sequence item](https://documentation.help/DirectMusic/dmusioseqitem.htm) and [instrument record](https://documentation.help/DirectMusic/dmusioinstrument.htm).

This is an intentional native synthesis replacement, not a sample-identical implementation of Microsoft's synthesizer. Reverb, chorus/other audio-path DSP and channel-pressure curves are not implemented by this backend. Instrument synthesis, modulation, variation timing and notes crossing a loop boundary may differ. The game quality/voice-count settings do not select the former DirectMusic hardware paths. Other game variants and custom music require their own validation.

Adapter/manager syntax checks cover x86/x64, Debug/Release. The patched library passes x64 Debug/Release C11 syntax checks with existing upstream narrowing/type warnings. These checks do not restore/build/link the package or play music. A user rebuild must still validate dependency restoration, audible menu/mission music, event changes, looping after the intro, volume/mute, speech ducking, repeated game/menu transitions and clean shutdown. Use `-log:renderer` for diagnostics.

The first user build successfully installed both configurations of the static libraries but exposed the nested public-header path. Revision 2 corrects the install rule. A separate header-copy check verifies the corrected CMake directory layout; adapter syntax checks use that installed header directory. Rebuilding/restoring revision 2 and linking the game remain user validation steps.

The subsequent user x64 Debug run reached PCM rendering and exposed a null global style in the library's random-pattern selector. The original fallback groove command was created even for scores without an external style, and some of its fields were uninitialized. Revision 3 schedules a zero-initialized fallback only at the first external-style activation, skips global-style selection for independent tracks and handles missing/empty styles. All 64 inspected game scores use embedded patterns or sequence tracks without external style/command tracks. Syntax and patch checks pass; a user rebuild and playback confirmation remain pending. This supersedes the preceding revision-2 restore/link checkpoint.

Revision 4 corrects a temporary message queue whose initializer assumed previously zeroed storage. The user Debug stack reaches `handlePatternTrack -> MessageQueue_init -> growQueue`; the reported 7,378,697,629,483,821,440-byte request equals `(0xCCCCCCCCCCCCCCCC + 100) * 8` modulo 64 bits, using the uninitialized Debug capacity. Queue initialization now clears all fields, temporary storage is explicitly initialized, partial allocation failure releases owned blocks, release resets the owner, and growth checks addition/multiplication overflow. Source checks pass; user rebuild and playback confirmation remain pending.

Revision 5 handles missing optional DLS display names at all three sample/preset/instrument copy sites. The user's sample-conversion crash matches original `015.dls`: nine waves, first named `Flute C3`, 270,999 decoded samples including padding, and unnamed wave index 8 with 546 PCM bytes. A read-only inventory of 49 game collections plus Windows `gm.dls` finds exactly one unnamed wave and no unnamed instruments. Samples remain present and usable; naming does not select their bank/patch or alter their PCM. All three copies accept absent names and explicitly terminate the fixed-size destination. Source checks pass; user rebuild and audible validation remain pending.

Revision 6 follows the user's confirmation of audible music with low pitch and incorrect timing. The converter no longer subtracts an additional octave after applying the packed octave/root. Fixed-to-key/chord notes are interpreted as linear MIDI values, with the global key stored separately from a subchord's scale root; 12 original parts use fixed-to-key, while 597 use always-play. The [SDK note representation](https://documentation.help/DirectMusic/dmusnotepmsg.htm) and [Microsoft SDK play-mode definitions](https://raw.githubusercontent.com/milliet/DDReader/master/c/sdk-directx9/Include/dmusici.h) establish these units/modes. All 625 inspected channel references match their legacy logical channel, so channel remapping was not implicated. The default C-major-seven/major-scale context is inferred from all four shipped chord tracks; no system-DLL oracle was executed to establish a universal default. Original explicit chord messages retain priority.

The fractional clock retains sub-tick progress instead of rounding each PCM slice. Event dispatch rounds up to one complete output frame and keeps that residual time; buffer size and repeated render calls no longer add independent tick rounding. At 100 BPM/44,100 Hz, rounding each 1,024-frame slice previously gained about 11.99 music ticks per second. Sample rates and DLS wave contents are unchanged. Syntax, source/math, asset and patch checks do not establish audible equivalence; the user must rebuild and compare pitch, timing, loops and transitions with the original game. Reverb/DSP and other existing fidelity limits remain.

Revision 7 corrects start/stop and primary-transition scheduling following the user's report of missing background music and a lingering Frankish theme. Pending primary changes have their own retained owner and deadline, separate from score and loop messages. Rebuilding a score queue at a loop or stopping one segment cannot discard an unrelated requested change. The deadline is rebased when the score's local clock resets; a requested change wins over a simultaneous old loop. A later primary request replaces the pending request. Immediate segment-specific stop cancels the matching pending request and stops the matching current segment under the render lock; it does not enqueue a stop that can later erase a newly accepted start. Release and cancellation balance the pending owner's reference.

The playback query now describes only the current rendered segment, as specified by the [Microsoft SDK IsPlaying contract](https://documentation.help/DirectMusic/idirectmusicperformance8isplaying.htm); a queued start or a future loop is not current playback. The game retains its 0x2000 measure-boundary requests, identified by Microsoft's dmusici.h as DMUS_SEGF_MEASURE. With no primary segment, a request starts without waiting for a fabricated idle measure; an exact boundary adds no extra measure. The game does not request TIMESIG_ALWAYS. This is a repair of the native adapter/library contract, not a change to diplomacy, visibility, mission/theme tables, music randomness or save format.
